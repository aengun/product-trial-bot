# 무신사 체험단 자동 신청 봇

실제 무신사 공고를 수집하고, 설정한 조건에 맞는 상품·사이즈를 골라 **Orca 내장 브라우저**에서 신청합니다. Chrome이나 별도 브라우저를 띄우지 않습니다. Node.js 22 이상과 Orca 앱이 필요하며, Orca 안의 터미널에서 실행합니다.

봇은 Orca 브라우저에 **봇 전용 탭**을 하나 열어 계속 사용합니다(`.bot/orca-tab.json`에 탭 번호를 기억). 로그인은 Orca 브라우저에 남아 같은 프로필의 탭과 공유되며, 사용자가 보고 있는 다른 무신사 탭은 건드리지 않습니다. 봇 탭을 닫아도 다음 실행 때 새로 엽니다. 봇이 실행 중일 때 봇 탭에서 직접 이동하거나 클릭하지 마세요.

```sh
npm install
npm run init
npm run login
npm start
```

`npm start`는 **옵션 미리보기**입니다. 신청 버튼·동의 체크박스·제출을 누르지 않습니다. 공고와 선택 예정 옵션은 터미널 및 `.bot/last-run.json`에 표시됩니다. `npm run scan`은 상품 실측 확인 없이 공고만 수집합니다.

실제 신청은 로그인과 필수 동의를 설정한 뒤 실행합니다.

```sh
npm start -- --submit
```

반복 실행은 `npm start -- --submit --watch`입니다. 현재 예시는 한국 시간 매일 오전 08시에 확인합니다. 한 회차의 신청 후보 상한은 5개이며, Slack 승인 알림은 개수 제한 없이 이어서 보냅니다. Ctrl+C로 종료합니다. 로그인·추가 인증·사이트 접근 제한을 만나면 중단합니다.

## 개인 설정

`config.json`은 `npm run init`으로 생성합니다. 기존 설정은 덮어쓰지 않습니다. 현재 예시는 요청한 172cm·65kg, 상의 M/L, 하의 29/30, 신발 260을 반영합니다. 아우터·생활용품·뷰티·패션 소품 등을 포함한 **키즈를 제외한 전체 카테고리**에서 남성·공용만 수집합니다(`gender: "M"`). 여성·우먼·women 등 여성용 표시가 있는 공고와 상품·옵션도 제외합니다. 특정 공고 번호를 지정해도 이 필터를 적용합니다.

| 설정 | 동작 |
| --- | --- |
| `categories` | 무신사 카테고리 이름 배열. `전체` 또는 원하는 카테고리들 |
| `gender` | `A`: 전체, `M`: 남성·공용, `F`: 여성·공용 |
| `includeKeywords` | 제목·브랜드 중 하나라도 포함하면 허용. 빈 배열은 전체 |
| `excludeKeywords` | 포함된 공고 제외. 포함 조건보다 우선 |
| `brands` | 정확히 일치하는 브랜드 이름만 허용 |
| `campaignIds` | 특정 체험단 번호만 실행할 때 사용 |
| `profile` | 사이즈 및 상의 실측 비교 기준 |
| `preferredOptions` | 프로필을 `null`로 둘 때 사용할 정확한 옵션 이름 |
| `campaignOptions` | 체험단별 정확한 옵션 이름. 자동 사이즈 비교보다 우선 |
| `acceptedConsentIds` | 직접 확인하고 수락한 필수 약관 ID |
| `maxPages` | 카테고리마다 읽을 최대 페이지 수. 페이지당 18개 |
| `maxApplicationsPerRun` | 한 회차에서 신청을 준비할 후보 수 상한 |
| `excludeCategories` | 알림·신청에서 제외할 카테고리. 현재 `키즈` |
| `excludeFemaleCosmetics` | 여성용 색조 화장품 제외. 남성용으로 명시한 제품·일반 스킨케어는 유지 |
| `intervalSeconds` | `schedule`이 없을 때의 반복 대기 시간. 최소 60초 |
| `schedule` | 한국 시간의 고정 확인 시각. 예시: 매일 오전 08시 |
| `actionDelayMs` | 페이지·공고 처리 사이 간격. 최소 500ms |
| `sizeReview.scoreGap` | 상의 두 사이즈의 적합도 점수 차이가 이 값 이하면 확인 요청. 기본 2 |
| `sizeReview.boundaryCm` | 실측이 허용 범위 경계에서 이 거리 이내면 확인 요청. 기본 1cm |
| `notifications.desktop` | 맥 알림 사용. 기본 `true` |
| `notifications.terminal` | 터미널 확인 알림 사용. 기본 `true` |
| `notifications.slack` | Slack Incoming Webhook 알림 사용. 기본 `false` |

상의는 상품의 **총장·가슴단면 cm 실측**(상품 페이지 실측표와 같은 데이터를 API로 읽고, 읽지 못하면 상품 페이지 표를 사용)을 읽고, 재고가 있는 M/L 중 설정한 목표 실측과 가까운 쪽을 선택합니다. 초기 기준은 가슴단면 50~62cm·총장 63~72cm, 목표 가슴단면 55cm·총장 68cm입니다. 이는 172cm·65kg에 맞춰 둔 **초기 가정값**이며, 키·몸무게로 실제 가슴둘레나 선호 핏을 계산한 값은 아닙니다. 잘 맞는 옷의 실측으로 `profile.topFit`을 조정하면 비교가 더 정확해집니다. 실측표가 이미지로만 있거나 기준을 벗어나면 보류합니다. XL, FREE, S 등으로 임의 대체하지 않습니다.

하의는 지정한 순서인 29→30 중 재고가 있는 사이즈를, 신발은 정확히 260을 선택합니다. 단독 표기 `260mm`도 인식하지만 `260~265`, `M(95)` 같은 복합 표기를 추측해 변환하지 않습니다. 일반 미리보기·자동 신청은 대표 상품과 제목에 맞는 색상을 우선합니다. Slack 승인 모드는 모든 상품의 재고가 있는 색상·사이즈 조합을 버튼으로 표시하며, 클릭한 SKU를 그대로 신청합니다.

아우터는 상의와 같은 M/L 실측 기준을 사용합니다. 생활용품·뷰티·소품 등은 의류 사이즈를 요구하지 않습니다. 신청 가능한 옵션이 하나면 그 옵션을 표시하고, 여러 개면 `옵션1`, `옵션2`처럼 실제 구성과 함께 확인을 요청합니다. 공용 커플 상품 안의 `(여)` 등 여성용 옵션도 제외합니다.

일반 판매 중이 아니더라도 모집 중인 체험단에 재고 옵션이 있으면 신청 후보로 확인합니다. 실제 신청 조건은 사이트의 신청 화면에서 다시 확인합니다.

## 사이즈가 애매할 때 알림

실측표를 읽을 수 없거나, M/L의 적합도 차이가 작거나, 실측이 설정한 범위 경계에 가까우면 해당 공고를 **사이즈 확인 대기**로 저장하고 신청을 보류합니다. `260~265`처럼 옵션 표기가 애매한 경우도 확인을 요청합니다. 명백한 품절은 일반 건너뛰기로 처리합니다. 나머지 공고는 계속 처리합니다.

기본값은 맥 알림과 터미널 알림입니다. 상품명·공고 링크·확인 이유를 알리고, 대기 목록에서는 선택 가능한 사이즈와 읽을 수 있었던 실측 비교를 함께 보여줍니다. 같은 공고의 확인 이유·재고 사이즈·비교 실측이 같으면 이미 보낸 알림을 반복하지 않습니다. 알림 요청 실패는 다음 회차에 다시 시도합니다. 맥 알림은 한 회차에 최대 3개 요청하고, 나머지는 대기 목록에 저장한 뒤 다음 회차에 알립니다.

```sh
npm run notify:test
npm run reviews
npm run choose -- 49595 M
```

`choose`의 체험단 번호와 사이즈는 실제 대기 목록에 나온 값으로 바꿉니다. 봇의 반복 실행 중에도 별도 터미널에서 사용할 수 있습니다. 선택한 사이즈는 다음 실행에서 재고를 다시 확인해 적용합니다. 반복 실행이 꺼져 있다면 `npm start`로 미리보거나 `npm start -- --submit`으로 신청합니다. 이 선택은 해당 공고에만 적용하며 기본 M/L 프로필을 바꾸지 않습니다.

봇은 `needs-size-review` 상태를 저장하고, 사용자 선택 전에는 신청서 준비·제출을 호출하지 않습니다. 선택한 상품 구성이 바뀌거나 사이즈가 품절되면 다시 확인을 요청합니다. 대기 목록과 선택은 재시작 후에도 유지됩니다.

맥 알림 요청은 macOS의 AppleScript 알림을 사용합니다. 배너 표시는 시스템 알림 설정과 집중 모드에 따라 달라집니다. `npm run notify:test`를 실행해 확인하고, 필요하면 시스템 설정 → 알림에서 Script Editor(스크립트 편집기)의 표시를 허용하세요. 터미널 알림과 `npm run reviews`는 배너 표시 여부와 관계없이 사용할 수 있습니다. 봇이 실행 중일 때 발견한 공고를 알리므로 계속 확인하려면 `--watch`로 실행합니다.

## 슬랙으로 알림 받기

Slack Incoming Webhook을 연결하면 사이즈 확인이 필요한 공고를 슬랙 채널로 보냅니다. 상품명, 선택 가능한 사이즈와 실측, 사이즈 선택 명령을 간단히 표시하며, 공고는 **무신사 공고 열기** 링크로 연결합니다.

`From scratch` 선택지가 보이지 않으면 [Slack 공식 알림 앱 생성 링크](https://api.slack.com/apps?manifest_json=%7B%22display_information%22%3A%7B%22name%22%3A%22Webhook+alerts%22%2C%22description%22%3A%22Posts+Webhook+notifications+to+a+Slack+channel.%22%7D%2C%22features%22%3A%7B%22bot_user%22%3A%7B%22display_name%22%3A%22Webhook+alerts%22%2C%22always_online%22%3Afalse%7D%7D%2C%22oauth_config%22%3A%7B%22scopes%22%3A%7B%22bot%22%3A%5B%22incoming-webhook%22%5D%7D%7D%2C%22settings%22%3A%7B%22incoming_webhooks%22%3A%7B%22incoming_webhooks_enabled%22%3Atrue%7D%2C%22org_deploy_enabled%22%3Afalse%2C%22socket_mode_enabled%22%3Afalse%2C%22token_rotation_enabled%22%3Afalse%7D%7D&new_app=1)를 사용합니다. 알림에 필요한 설정이 채워진 생성 화면으로 이동합니다. 워크스페이스 선택 후 설정을 검토해 앱을 생성하고 아래 3번의 채널 연결을 진행합니다. 이 링크는 [Slack 공식 문서](https://docs.slack.dev/)의 `Create the webhook app`과 같은 설정입니다.

1. [Slack 앱 관리](https://api.slack.com/apps)에서 앱을 만들거나 기존 앱을 엽니다.
2. **Incoming Webhooks → Activate Incoming Webhooks**를 켭니다.
3. **Add New Webhook to Workspace**에서 본인 알림용 채널을 선택하고 허용합니다. 발급 주소는 그 채널로 메시지를 보내는 데 사용됩니다. [Slack 공식 연결 안내](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)
4. 로컬 `.env`에 `SLACK_WEBHOOK_URL=발급받은주소`를 저장하고, `config.json`의 `notifications.slack`을 `true`로 설정합니다. `.env.example`을 복사해 시작해도 됩니다. `.env`는 봇 실행 시 자동으로 읽으며 Git에 포함하지 않습니다.

슬랙만 사용하려면 설정을 다음처럼 바꿉니다.

```json
{
  "notifications": { "slack": true, "desktop": false, "terminal": true }
}
```

```sh
npm run notify:test
npm start -- --watch
```

첫 명령은 설정한 채널에 **테스트 메시지를 실제 전송**합니다. 두 번째 명령은 미리보기와 알림만 반복합니다. 실제 신청도 반복하려면 `npm start -- --submit --watch`를 사용합니다.

Incoming Webhook 모드는 알림을 보내는 방식입니다. 이 모드의 사이즈 결정은 슬랙 메시지에 표시된 `npm run choose -- 체험단번호 사이즈` 명령으로 입력합니다. 슬랙 답장으로 승인하려면 아래 Socket Mode 연동을 사용합니다.

한 회차에 슬랙 메시지를 최대 3개 보내고, 나머지는 대기 목록에 보관해 다음 회차로 넘깁니다. 전송은 1.1초 이상 간격을 두고, 429 응답을 받으면 `Retry-After`가 지난 뒤에 시도합니다. HTTP 200 및 `ok` 응답을 확인한 항목에 채널별 중복 방지를 적용하므로 재시작해도 같은 알림을 다시 보내지 않습니다. 응답이 유실되면 다음 시도에 메시지가 중복될 수 있습니다.

웹훅 주소는 설정·실행 로그·슬랙 메시지에 넣지 않습니다. 공개 상품 정보와 확인 요청만 전송하며, 계정 쿠키·비밀번호·배송지·키와 몸무게는 메시지에 포함하지 않습니다. 실제 채널 연결 검증은 웹훅 설정 후 `npm run notify:test`로 진행합니다.

## 슬랙 옵션 버튼으로 신청 승인

```sh
npm run login
npm run slack:start
```

이 모드는 신청 예정 옵션을 슬랙에 보내고 **본인 승인 후에만** 무신사 신청을 진행합니다. 정상 사이즈도 승인을 기다립니다. 기존 `npm start -- --submit --watch`는 기존 자동 신청 방식입니다.

알림마다 `━━ 체험단 #49245 · 상의 ━━`처럼 번호·분류 구분 문구와 구분선을 넣습니다. 짧은 상품명과 옵션 버튼, **공고 보기** 하이퍼링크만 표시합니다. 예를 들어 색상 4개와 사이즈 4개가 모두 재고가 있으면 16개 버튼을 보냅니다. 품절 조합과 여성용 옵션은 제외합니다. 키즈는 카테고리와 키즈·주니어·아동 등의 이름으로 제외합니다. 공용으로 분류됐더라도 틴트·파운데이션·마스카라 등 색조 화장품과 컬러·플럼핑 립밤은 제외하며, 남성용으로 명시된 화장품과 일반 스킨케어·무색 립밤은 유지합니다. 뷰티 이외의 생활용 쿠션 등은 이 색조 필터로 제외하지 않습니다.

처음에는 특정 공고 하나로 확인할 수 있습니다.

```sh
npm run slack:start -- --campaign-id 49540
```

원하는 색상·사이즈 **버튼을 한 번 누르면 바로 신청을 승인**합니다. 별도로 댓글을 입력하거나 다시 승인할 필요가 없습니다. 아무것도 누르지 않으면 신청하지 않습니다.

텍스트로 선택하려면 해당 알림의 스레드에 `옵션2` 또는 `2`처럼 표시된 옵션 번호만 답장해도 됩니다. 색상이 여러 개인데 `M`만 입력한 경우처럼 조합이 모호하면 임의로 선택하지 않습니다. 기존 `승인 옵션2`, `블랙 / M` 같은 답장도 정확한 조합 하나로 확인될 때 처리합니다.

현재 설정은 매일 한국 시간 오전 08시에 모집 중이고 필터를 통과한 미신청 공고 중 아직 알림을 보내지 않은 공고를 모두 안내합니다. 새 승인 알림은 5건씩 묶어 같은 회차에서 다음 묶음을 계속 보냅니다. 예를 들어 30건이면 다음 날을 기다리지 않고 6묶음을 이어서 보냅니다. 각 메시지는 1.1초 이상 간격을 두고 전송하며, `maxApplicationsPerRun`은 실제 신청 후보 수에만 적용합니다. 이미 알림을 보낸 승인 대기 공고와 거절한 공고는 다시 알리지 않습니다. 중간에 봇을 재시작해도 다음 정기 시각을 기다립니다.

옵션 선택과 신청 결과 회신은 정기 알림 시간과 별도로 처리합니다. 선택을 받으면 대기 중인 반복 실행을 깨워 승인된 공고만 신청하고 결과를 같은 스레드로 회신합니다. 이때 다른 신규 공고 알림을 보내지 않습니다. 다른 공고를 확인 중이면 현재 확인 회차가 끝난 뒤 진행합니다. 접수된 알림의 버튼은 제거하고, 반복 클릭은 다시 신청하지 않습니다.

### 슬랙 앱 연결 설정

기존 Incoming Webhook 주소만으로는 답장을 수신할 수 없습니다. [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/)와 [메시지 이벤트](https://docs.slack.dev/tools/bolt-js/concepts/message-listening/)를 추가합니다. 공개 서버나 외부 접속 주소를 열 필요는 없습니다.

1. [Slack 앱 관리](https://api.slack.com/apps)에서 기존 앱을 열고 **App Manifest**에 [slack-app-manifest.json](./slack-app-manifest.json)의 설정을 반영합니다. 이름을 유지하려면 `display_information.name`을 기존 이름으로 바꿉니다. 필요한 Bot Token Scopes는 `chat:write`, `channels:history`, `groups:history`, 기존 `incoming-webhook`이며, Bot Events는 `message.channels`, `message.groups`, Socket Mode와 Interactivity는 On입니다(`settings.interactivity.is_enabled: true`).
2. **OAuth & Permissions → Reinstall to Workspace**에서 변경된 권한을 확인하고 설치한 뒤 **Bot User OAuth Token**(`xoxb-`로 시작)을 `.env`의 `SLACK_BOT_TOKEN`에 넣습니다.
3. **Basic Information → App-Level Tokens → Generate Token and Scopes**에서 `connections:write` 권한으로 토큰을 발급하고 `.env`의 `SLACK_APP_TOKEN`에 넣습니다. 이 값은 `xapp-`로 시작합니다.
4. 본인 프로필의 **멤버 ID 복사** 값을 `.env`의 `SLACK_APPROVER_USER_ID`에 넣고, 알림 채널 상세 정보의 채널 ID를 `SLACK_CHANNEL_ID`에 넣습니다.
5. 해당 슬랙 채널에 봇을 초대한 뒤 `npm run slack:start`를 실행합니다. 무신사 기본 배송지와 `acceptedConsentIds` 설정도 필요합니다.

`.env.example`에 네 설정 칸이 있습니다. 기존 `SLACK_WEBHOOK_URL`은 그대로 사용할 수 있습니다. 새 토큰을 코드·로그·채팅에 넣지 않습니다.

앞서 Webhook으로 보낸 일반 알림의 스레드는 승인 요청으로 등록돼 있지 않습니다. Socket Mode 연결 후 새로 보내는 **신청 승인 요청**의 스레드에서 답장해야 합니다. 등록된 승인 알림의 옵션 버튼과 텍스트 답장을 처리합니다.

### 승인 처리와 복구

설정한 본인의 버튼 클릭과 새 답장만 처리합니다. 워크스페이스·채널·알림 스레드가 모두 일치해야 하고, 봇 메시지·수정된 메시지·중복 이벤트는 승인을 만들지 않습니다. 승인 요청은 공고 모집 마감까지 유효합니다. 기존에 24시간으로 만료 시각을 정했던 승인 대기 알림도 재시작 시 모집 마감까지 연장하므로 원래 알림에서 승인할 수 있습니다. 모집 마감일이 없는 공고는 24시간으로 제한합니다.

봇을 재시작하면 아직 유효한 승인 대기 스레드의 실제 댓글 기록을 읽어, 봇이 꺼져 있을 때 놓친 답장을 복구합니다. 본인 댓글만 시간순으로 처리하고 이미 처리한 댓글·수정된 댓글은 다시 승인하지 않습니다. 복구에 실패하면 터미널에 알리며 새 답장 수신은 계속합니다. 이전 알림을 버튼 방식으로 갱신할 때는 과거의 선택만 저장했던 댓글을 새 신청 지시로 해석하지 않으며 오래된 버튼도 무효화합니다.

승인한 **상품·SKU·색상·사이즈**를 저장하고, 제출 직전의 옵션과 같을 때만 실행합니다. 옵션이 바뀌면 새 승인 요청을 보냅니다. 이미 소비한 승인은 다시 실행하지 않습니다. 제출 후 응답이 끊기면 재신청을 막고 무신사 내역 확인을 요청합니다. `npm run approvals`로 승인 요청 상태를 볼 수 있습니다.

기록은 `.bot/slack-approvals/`에 저장합니다. 실제 제출 결과가 불확실하면 무신사 내역을 확인한 뒤 기존 `resolve ID --applied` 또는 `resolve ID --retry` 명령으로 처리합니다. 재시도를 허용하면 이전 슬랙 승인은 종료하고 새 승인을 요구합니다. 슬랙 메시지 전송 자체가 불확실한 경우에는 같은 승인 알림을 자동 재전송하지 않습니다.

2026-11-07 실제 계정에서 Slack의 `승인 M` 답장 수신, Orca 탭의 무신사 신청 2건, 같은 스레드의 신청 완료 회신까지 확인했습니다. 자동 테스트는 가짜 Slack 전송과 로컬 브라우저 시험 화면을 사용합니다.

2026-11-08 옵션 버튼·번호 선택 후 로컬 신청과 중복 방지를 검증했고, 실제 Slack의 테스트 버튼이 Socket Mode로 수신되는 것도 확인했습니다. 기존 알림 144건을 갱신하고 원격 메시지의 버튼과 저장된 SKU를 대조했습니다. 4104 후디는 4색 × 4사이즈의 16개 버튼을 표시합니다. 연결 테스트 버튼은 실제 상품 신청을 하지 않으며 검증 후 삭제했습니다.

원하는 옵션을 직접 정할 수도 있습니다. 예를 들어 아래 설정은 해당 체험단에서 차콜/M만 선택합니다. 설정한 사이즈·색상의 조합이 품절이면 다른 것으로 바꾸지 않습니다.

```json
{
  "campaignOptions": {
    "49595": ["차콜", "M"]
  }
}
```

## 로그인과 필수 동의

`npm run login`을 실행하면 Orca의 봇 탭이 앞으로 나옵니다. 이미 Orca 브라우저에서 무신사에 로그인돼 있으면 그대로 사용하고, 아니면 그 탭에서 직접 로그인한 뒤 터미널에서 Enter를 누릅니다. 비밀번호를 코드·설정에 넣을 필요가 없습니다. 기본 배송지와 사이트에서 요구하는 수신 동의·본인인증도 직접 확인합니다. Chrome 프로필이나 쿠키를 가져오지 않습니다.

현재 신청서에는 아래 네 가지 필수 동의가 있습니다. 실제 신청서의 **자세히**에서 내용을 확인하고, 수락한 항목만 `config.json`의 `acceptedConsentIds` 배열에 넣습니다. 기본값은 빈 배열입니다. 회원 등급 조건과 상품별 제세공과금 등 유의 사항도 신청서에서 확인할 수 있습니다.

| ID | 신청서 항목 |
| --- | --- |
| `privacy_collection` | 개인정보 수집 및 이용 동의 |
| `privacy_third_party` | 개인정보 제 3자 제공 동의 |
| `penalty_policy` | 이벤트 당첨자의 패널티 정책 동의 |
| `auto_payment` | 이벤트 당첨 시 '0원 자동 결제' 동의 |

봇은 설정된 네 항목만 체크합니다. 새로운 동의 항목, 배송지 미등록, 등급 제한, 추가 인증 등이 있으면 제출하지 않습니다. 선택한 상품·SKU가 계획과 같은지도 제출 전에 확인합니다.

## 기록과 복구

`npm run status`로 기록을 확인합니다. `.bot/campaigns.json`에는 수집 공고, `.bot/last-run.json`에는 마지막 실행 결과, `.bot/state.json`에는 체험단별 처리 상태가 저장됩니다. 로그인 세션은 Orca 브라우저에 있고 봇은 따로 저장하지 않습니다. `.bot/orca-tab.json`은 봇 탭 번호만 담습니다. `.bot/`과 `config.json`은 Git에서 제외합니다. 신청서 개인정보나 쿠키를 로그에 덤프하지 않습니다.

제출 직전에 `submitting`을 저장하고, 화면에서 성공 문구를 확인한 뒤 `submitted`로 바꿉니다. 네트워크 끊김·프로세스 종료로 결과가 불확실하면 `submitting` 또는 `uncertain` 상태로 남겨 자동 재시도를 막습니다. 무신사 신청 내역에서 결과를 확인한 뒤에만 다음 중 하나를 실행합니다.

```sh
node src/cli.js resolve 12345 --applied
node src/cli.js resolve 12345 --retry
```

같은 데이터 폴더에서는 봇·로그인 명령을 동시에 실행할 수 없습니다. `reviews`와 `choose`는 실행 중인 봇과 함께 사용할 수 있습니다. 사용자 사이즈 선택은 `.bot/size-decisions/`에 저장합니다. 비정상 종료 후 잠금이 남았으면 기존 봇 프로세스가 종료됐는지 확인한 뒤 `.bot/run.lock`을 삭제합니다. 동일 계정은 하나의 데이터 폴더로 운용하세요.

## 검증과 지원 범위

```sh
npm test          # 단위 검증 (Orca 없이 실행)
npm run test:orca # Orca 내장 브라우저 통합 검증 (Orca 앱 필요, 시험용 탭을 열었다 닫음)
```

`npm test`는 Orca 브라우저 시험 8개를 건너뜁니다. `npm run test:orca`는 Orca에 시험용 탭을 열고 로컬 시험 서버로 전체 흐름을 검증합니다. 미리보기의 제출 방지, 재고·실측 선택, 상품/SKU 일치 확인, 필수 동의 누락, 색상·사이즈 조합 버튼과 옵션 번호 승인, 중복 신청 및 제출 응답 유실 후 재시도 방지를 검사합니다. 테스트는 무신사에 신청하지 않습니다.

2026-11-07 기준 Orca 내장 브라우저에서 실제 무신사 공고 수집, 로그인 확인, 실측 읽기·옵션 계획, 신청서 이동과 SKU 일치 확인, 필수 동의 체크 및 실제 제출까지 확인했습니다. Slack에서 승인한 M 사이즈 후드티 2건의 신청 완료 문구와 사이트의 신청 여부, Slack 결과 회신을 확인했습니다. 로그인 해제 시에는 제출 전에 중단했으며, 다시 로그인한 뒤 저장된 승인으로 진행했습니다. 상의 20개 상품에서 실측 API와 상품 페이지 실측표가 같은 값임을 확인했습니다. 비공개 API의 직접 제출 대신 사이트 신청 화면을 사용합니다. 무신사 화면·내부 읽기 API가 바뀌면 수정이 필요할 수 있습니다. CSS 옵션 선택기는 `selectors` 설정으로 교체할 수 있습니다. CAPTCHA나 접근 제한을 우회하는 기능은 없습니다.
